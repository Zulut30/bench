## Подтверждённая граница

- TypeScript strict, чистый npm ci, закреплённый lockfile, promptfoo как движок.
- 16 задач / все primary категории, smoke 6, настраиваемые попытки. Тесты принимают
  32 разные правильные реализации и отклоняют 16 содержательных дефектов.
- Настоящие Node HTTP, SQLite, strict TS и Chromium в ограниченном контейнере;
  test-writing обнаруживает четыре мутанта. PNG и реальные версии браузера/шрифтов сохранены.
- Проверена недоступность env-секретов, host project/auth, hidden checker и внешней
  сети; недоверенный процесс UID 10001 без capabilities. CPU/memory/pids/time/output ограничены.
- SQLite с атомарным reserve/state/settlement, межпроцессной защитой, сохранной
  миграцией. SIGKILL planned/reserved/dispatched/received/completed/failed/in_doubt/
  finalizing, replay без повторной отправки неизвестного исхода, восстановление хвоста.
- UTF-8 stdout/stderr по байтам, unknown vs 0, cache/reasoning без двойного счёта,
  модель/судьи/retries/подписки отдельно. Квота, timeout, bad JSON, Ctrl+C/130.
- Сравнение разных клиентов и endpoint, слепое A/B/реальные PNG/swap-order,
  случайная ручная выборка 10% + споры. Fresh suspected rerun, immutable export/resume.
- README содержит явные команды ограниченного live run и GET-сверки; по умолчанию mock.

«Проверено заглушкой» подтверждает контракт приложения, не доступность модели аккаунту
и не точность реального биллинга. До live-проверки подключения считаются предварительными.

## Остаточные ограничения

1. 16 диагностических задач, одна на категорию, недостаточны для уверенного рейтинга.
   DevOps проверяет Dockerfile-контракт + start.sh/health, а не сборку произвольного
   Dockerfile. Текстовые проверки ограничены указанными фактами/форматом; смысл,
   естественность, архитектурные обоснования и эстетика остаются pending.
2. Для реального OpenRouter не опубликована гарантированная граница upstream framing
   конкретного запроса. Поэтому используется context fallback, а не оценка символы/4.
   Literal Llama3 byte-bound проверен локальным контрактом; tokenizer family не
   подтверждает framing. Высокий резерв может отклонить дешёвую короткую задачу.
3. При сбое до получения generation ID требуется сопоставление с Activity. Неизвестный
   расход удерживает резерв. Сверка не восстанавливает потерянный ответ и не отправляет
   запрос повторно. Журнал охватывает этот results-dir, не сторонние вызовы того же ключа.
4. CLI не раскрывает все внутренние retries/usage, температуру и иногда actual model.
   Это null/неполнота. Codex/Gemini output — наблюдаемый предел; quota не угадывается.
   Claude overage-disabled — заявление пользователя, серверный переключатель не проверяется.
5. Одна рабочая станция / один results-dir; distributed leasing, сетевые SQLite,
   долгосрочное расписание, панель и публикация отсутствуют. PID lease консервативен
   при reuse PID. Статистическая уверенность и причинность изменений не вычисляются.
6. Проверено на macOS arm64 + Colima и Linux amd64 в CI указанного выше commit.
   Результаты последующих изменений следует смотреть для их конкретного commit.
   Windows/WSL/rootless Docker отдельно не проверены.
7. npm audit после чистой установки: **3 high** из одной транзитивной цепочки
   node-forge 1.4.0 → jks-js → promptfoo 0.123.1. Advisory
   [GHSA-86w9-cpqp-85rv](https://github.com/advisories/GHSA-86w9-cpqp-85rv)
   относится к RSA PKCS#1 v1.5 verification; исправленного forge в npm на дату проверки нет.
   JKS/custom certificate handling в текущих подключениях не используется, но аудит
   зависимостей остаётся незелёным. Это не утверждение об отсутствии уязвимостей.
   basic-ftp обновлён проверенным override 6.2.1 по
   [GHSA-c475-qrg2-pj4r](https://github.com/advisories/GHSA-c475-qrg2-pj4r).
   Автоматический downgrade promptfoo 0.116.7 не применялся.

Готовность распространяется на локальную проверенную основу и ограниченный пробный
запуск с явным бюджетом. Она не означает подтверждённую live-готовность интеграций,
полную защиту от контейнерных/kernel уязвимостей или аттестованный production сервис.
